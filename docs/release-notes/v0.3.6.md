# EnduranceTrio Community - Release v0.3.6

This patch release completes the historical coverage of the 1987 Portuguese triathlon season, adding the results of the seven remaining events together with the athlete and team deduplication those results required. It also brings the H2 test migrations into parity with PostgreSQL and retires the obsolete static website and data-staging tooling.

## Breaking Changes

None.

## Features and Enhancements

### Core Logic & Business Rules

- **1987 second-semester results** — migration pairs `V20261101.002` and `V20261107.001`–`V20261107.006` load athletes, teams, individual results, team results, and team-member results for event IDs 17–23, covering the 1º Triatlo Lions Torres Novas, I Triatlo de Coimbrão, IV Triatlo de Peniche, I Triatlo de Ponte de Sor, I Triatlo da Associação de Comandos Porto, 1º Triatlo de Lagos, and I Triatlo de Grândola.
- **Result corrections** — migration `V20261101.001` fixes a team-result race assignment and merges athlete 455 into 314.
- **Athlete deduplication and data corrections** — migration `V20261107.007` merges athletes 552 into 230 and 711 into 629, corrects the names of athletes 48 and 629, and reassigns the results recorded under athlete 384 to athlete 250 for races 22, 24, 34, and 36.
- **DNF results** — migration `V20261107.008` records the DNF results of athlete 629 for races 19 and 21.
- **Team consolidation** — migration `V20261107.009` merges teams 59, 66, and 94 into team 10, renames team 10 to NAC, and normalizes the "NAC Martano" team name in individual and team results.

## Refactoring & Technical Debt

- **H2 migration parity** — every PostgreSQL DML migration now has an H2 counterpart except the PostgreSQL-only São Martinho insight-article script, and the sequence restart values in the 1985 and event-4 H2 scripts were corrected to match PostgreSQL.
- **Legacy static website removal** — the pre-application static `html/` website, no longer deployed, has been deleted.
- **Data-staging tooling removal** — the externalized historical-data staging tooling was retired and its dedicated resource and SonarQube exclusions were dropped from `endurancetrio-data/pom.xml` and `sonar-project.properties`.
- **Release image build** — the publish workflow now pulls the latest `eclipse-temurin:21-jre-alpine` base image before building, so images pick up current JDK and Alpine security updates.

## Documentation

- **Database reference** — `DATABASE.md` documents the eleven new migration pairs.
- **Maintainer guide** — `AGENTS.md` now refers to externally generated historical data instead of the retired data-staging tooling.
