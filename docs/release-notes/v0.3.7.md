# EnduranceTrio Community - Release v0.3.7

This patch release reworks the athlete profile around a renamed results model with numbered pagination, expands the reusable expand/collapse, box, tag and media styling system, and adds a style guide documenting the UI. It also hardens locale and security handling, improves query pagination performance, and exempts the FCCDCF consent cookie from a ModSecurity rule.

## Breaking Changes

None.

## Features and Enhancements

### API & User Facing Changes

- **Athlete profile page** — reworked results section with refreshed markup and styling, wired to the new expand/accordion behaviours.
- **Athlete results pagination** — numbered, windowed pagination with first/last links and ellipsis gaps, matching the athletes listing.
- **Athletes search button** — shows a Bulma loading spinner while the search request runs, via a reusable loading-button behaviour.
- **Athlete profile splits** — horizontal scroll region on mobile with an edge-shadow affordance and a one-time nudge toward hidden content.
- **Expand/collapse behaviour** — reusable expand/collapse for boxes and table rows (renamed from `bulma-table-expand` to `endurance-expand`), driven by `data-expand` hooks.
- **Box, tag and media variants** — light, outlined and square box variants, an outlined tag variant (plus a small tag), and an `is-mobile` media modifier.

### Core Logic & Business Rules

- **Athlete results model** — the race list is renamed to results across `AthleteResultDTO`, `AthleteResultsPageDTO`, the service and controller layers, with explicit ID ordering so SQL `IN` does not reorder the page.
- **Relay team placements** — resolved through the new `TeamResultRepository` and `ResultPlacement` projection.
- **Race type classification** — race types grouped via `RaceTypeGroup`.

## Bug Fixes

### Critical & Production Fixes

- **ModSecurity FCCDCF cookie** — exempt the Google Funding Choices consent cookie from CRS rule 942550 in the main and staging vhosts (rule IDs 1000001 and 1000002), preventing 403 responses; documented in `docs/deployment.md`.

### General Fixes

- **Newsletter sign-ups** — invalid submissions (missing first name or email) now redirect to the error page instead of returning 500.
- **Locale redirect** — `;jsessionid` path parameters are stripped before the redirect, ending redirect loops and 400 responses from the `StrictHttpFirewall`.
- **HEAD requests** — public pages now permit `HEAD`, so uptime monitors and crawlers no longer receive 403.
- **Language switch on error pages** — uses GET instead of POST, avoiding 403s from the web security chain.

## Performance & Optimizations

- **ID-first pagination** — event-by-year and athlete race lists paginate IDs before fetching entity graphs, avoiding Hibernate in-memory slicing (`HHH90003004`).
- **Auth filter registration** — `EnduranceTrioAuthFilter` is no longer auto-registered with the servlet container, so it runs once in the API chain instead of on every request and static asset.

## Refactoring & Technical Debt

- **Endpoint ordering** — deterministic route order (path, static before parameterized, shorter before descendants) applied to the mission and newsletter controllers.
- **Auth pre-check logging** — failures logged at `DEBUG` instead of `WARN`, reducing noise on anonymous requests.
- **SCSS partial reorganization** — scroll and grey-scale helpers moved into a `helpers/` directory to match Bulma's taxonomy.

## Documentation

- **Style guide** — new `docs/style-guide/` pages covering the palette, components, behaviours, icons and naming rules.
- **Release notes archive** — published notes moved from `tasks/` to `docs/release-notes/` and linked from the README.
- **Spring slice tests** — `docs/development.md` and `AGENTS.md` document when and how to use Spring context slice tests.
- **Deployment guide** — `docs/deployment.md` documents the FCCDCF ModSecurity exception and its verification steps.
- **Maintainer guide** — `AGENTS.md` updated with endpoint ordering, private member ordering and message-bundle rules.
- **Message bundles** — `MessagesBundleTest` keeps `messages.properties` and `messages_pt.properties` in sync.

## Dependency Updates

None.
